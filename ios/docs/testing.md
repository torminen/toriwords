# ToriWords for iOS: testing and parity fixtures

iOS and Android are separate native implementations that share no code. They must behave identically wherever the shared rules apply: text keys, IDs, clocks, merge, capture text rules, FSRS-6, the day model, the daily queue, the widget snapshot and multi-device sync. The shared definition of that behaviour is the set of JSON fixtures in `fixtures/`. This file says how the iOS suites run them, how the sync scenarios run against the in-memory CloudKit fake, and which behaviour is covered by iOS-only tests.

All iOS tests are Swift Testing (`@Test`) tests in the `ToriKit` Swift package (`ios/ToriKit/Tests`). There are no XCTest UI tests and no tests in the app target.

## 1. Rules

- **Fixtures are normative.** If this specification and a fixture disagree, the fixture wins and the text is fixed. The case format, comparison rules and the exact text-function character lists are in `fixtures/README.md`. Each fixture kind has a JSON Schema in `fixtures/schema/<kind>.schema.json`.
- **No per-platform skips.** `fixtures/known-deviations.json` must be `[]` before any release.

  > Not yet implemented on iOS: no iOS test or workflow reads `known-deviations.json`. The iOS suites run every case of every fixture file they load, so iOS has no skip mechanism at all.
- **Shared behaviour starts with a fixture.** A bug found on iOS in shared behaviour gets a fixture first. Then both platforms are fixed. Case IDs are stable and never renumbered or reused.
- **Fixtures are read in place**, never copied into the iOS tree.
- **Time is always explicit.** Tests never read the system clock or time zone. Every `now`, `reviewedAt` and `utcOffsetMin` comes from the case. `ToriStore` and `SyncEngine` take an injectable `now`; the tests pass a `TestClock`.
- **Comparison:** integers (days, intervals, counts, stage, offsets) exactly; `stability` and `difficulty` within a relative tolerance of `1e-9` (`SchedulerFixtureTests.swift`). Strings are compared by Unicode scalars, not by Swift `String` equality, which would treat canonically equivalent strings as equal.
- **Validation first.** CI validates every fixture against its schema in the shared `tools.yml` job (`cd tools/fixtures && uv run python validate.py && uv run pytest`). The same job checks that the generated `scheduler/` files are not stale and that fixtures use only code points assigned in Unicode 13.0.

**Fixture location** (`ios/ToriKit/Tests/ToriTestSupport/FixtureLocator.swift`): the environment variable `TORI_FIXTURES` wins when set and non-empty. Otherwise the root is derived from the source file's own path (`<repo>/ios/ToriKit/Tests/ToriTestSupport/` → `<repo>/fixtures`). CI sets `TORI_FIXTURES` to the checkout's `fixtures/`. The test `fixtureLocatorFindsSharedFixtures` fails if the folder cannot be found. `Fixture.swift` loads a file and turns each case into one test argument, so the test name prints the case ID.

| **Simulator (local)** | `xcodebuild test -scheme ToriKit-Package` on an iOS Simulator | By hand, before a release | all folders | Runs the iOS-only branches (`#if canImport(UIKit)` in `ToriUI` and `SpeechPlayer`) that the macOS run compiles out ([README](../README.md)). |

| **Performance** | — | — | — | Not yet implemented: no performance or launch-time tests. |

**Push to main runs no tests in `ios.yml`.** The merge of a pull request that already passed only builds the app. `toriKit-linux.yml` does run on pushes to main.

**Unicode on Apple platforms and Linux.** The quote, dash, space, whitespace and ignorable maps are explicit scalar lists in `TextKeys.swift`, so they cannot differ. Lowercasing and general-category checks use the Swift standard library's Unicode tables, which ship with the toolchain; NFC uses Foundation. The Linux run proves that the second implementation agrees on every fixture character.

## 4. Sync scenarios on the cloud fake

The scenarios in `fixtures/sync/` are written against an iCloud-like cloud: zones, change tags, accounts, `iCloudOff`. On iOS they need no translation. `SyncScenarioTests.swift` creates one `World` per case:
- one `InMemoryCloud` (`ios/ToriKit/Tests/ToriSyncTests/InMemoryCloud.swift`) with a cloud clock (`start` + `t`);
- per device, a real `ToriStore` in its own temporary directory and a real `SyncEngine`, with that device's clock offset (`clockOffsetSec`);
- record aliases from the steps, resolved to canonical Entry IDs on each device.

`InMemoryCloud` models the iCloud private database as the engine uses it ([sync.md](sync.md#cloud-fake-for-the-fixtures)):
- one zone per iCloud user, with a change log, `epoch:seq` change tokens and per-record change tags (system fields are `epoch:tag`);
- "if server record unchanged" saves: a stale change tag returns the server copy as a conflict;
- zone deletion by the app, and in iOS Settings (`userDeletedZone` until the app creates the zone again); a re-created zone is a new epoch;
- the `zone-info` generation marker, claimed by the first writer;
- a page limit for fetches (records, deletions and the marker count);
- scripted errors per operation and scripted per-record outcomes (used by the unit tests);
- a hook that runs code before the next save (used for `racedBy`).

Like CloudKit, it never merges or purges: every device merges and purges itself. The newest save wins.

### 4.1 Op mapping

| Fixture op / field | iOS meaning |
|---|---|
| `enableSync` (`account`) | The device's iCloud account becomes `account`, then one sync cycle runs (the first available account activates the outbox). |
| `sync` | One sync cycle (`SyncEngine.sync()`). |
| `sync` / `enableSync` with `limit` | Changes per fetched page; each page is one apply transaction. |
| `sync` with `racedBy: <device>` | That device's whole cycle runs right before this device's next save, so this device's save hits a stale change tag, merges the server copy and re-sends. |
| `cloudOff` | The device's iCloud account becomes unavailable. No cycle runs. |
| `cloudSwitch` (`to`) | The device's iCloud account becomes `to`: local words merge silently into that account's zone at the next cycle. No cycle runs. |
| `deleteCloudData` | "Delete iCloud data…" in the app (`SyncEngine.deleteCloudData()`). |
| `deleteCloudData` with `inSettings: true` | The user deletes the app's iCloud data in iOS Settings: the zone disappears and reports `userDeletedZone`. |
| `backUpAgain` | "Back up this device again". |
| `upgradeSchema` (`account`, `records`) | Records of a newer app version (higher `schema`, unknown fields or types) are injected straight into that account's zone, with clocks from the cloud clock and a fixed foreign node. |
| `network` (`online`) | The fake answers every call from that device with a network error while offline. |
| `setClock` (`offsetSec`) | The device clock is offset from the cloud clock. |
| `capture`, `editField`, `enrich`, `review`, `exclude`, `resume`, `delete`, `tag`, `untag`, `mergeByEdit`, `setSettings` | The same `ToriStore` operations the UI calls (`capture`, `setEntryText`/`setEntryNote`/`setEntryIPA`, `setStatus`, `deleteEntries`, `tag`/`untag`, `setEntryText(mergeIfDuplicate: true)`, `setNewWordsPerDay`, `setSchedulerParameters`). An unknown op fails the case. |

### 4.2 Expected-state mapping

| Fixture `expected` | iOS reading |
|---|---|
| `devices.<name>.sync.state` | The engine's `SyncState`, by name: `idle`, `syncing`, `synced`, `waitingForNetwork`, `iCloudOff`, `quotaFull`, `cloudDeleted`. |
| `devices.<name>.sync.user` | `sync_state.cloudUser`. |
| `devices.<name>.sync.outbox` | Distinct `record_id`s in `pending_changes` (including `_cloudDelete` rows). |
| `devices.<name>.words` | Live canonical Entries projected as text, note, IPA, status, `needsCheck`, translations, context sentences, sorted tag names, ReviewLog count and the `v` of each `extra` field; only the keys the fixture lists are compared. |
| `devices.<name>.settings` | `new_words_per_day`, `desired_retention`. |
| `devices.<name>.tombstones` | Each alias is a deleted Entry with no field values. |
| `cloud.<account>.entries` | Over the fake's current records for that account: live, deleted and merged Entry counts. |
| `cloud.<account>.types` | Record count per type. |
| `cloud.<account>.purged` | No record owned by the purged Entry remains, and the Entry itself, if present, is a value-less tombstone. |
| `converged` | These devices hold identical synced and derived rows of every type. `is_this_device` and `enrich_attempts` are left out, and so are the hidden children of deleted Entries (when they are purged may differ per device). |

## 5. iOS-only tests

Not part of the shared fixtures. Each runs in the macOS and Linux `swift test` runs unless noted.

| Area | Suite | What is tested |
|---|---|---|
| Store | `StoreTests` | Migrations and pragmas; fresh install then restore detection by `device-marker`; outbox written only while the outbox is active; an automatic write never overrides a user value; clock-ahead recovery re-stamps pending fields; merge by edit asks first, then merges deterministically; the post-pull merge picks the smallest ID and keeps history; tags merge by key and membership is OR; orphans then parent equal one page; delete wins, hides, purges and drops late children; unknown fields and types are kept; an incremental answer equals a full replay, and a parameter change rebuilds; Cards created when reviewable, with cloze for a highlighted sentence. |
| Queries and use cases | `StoreTests` | Inbox import is idempotent and ordered; search uses folds and escapes `LIKE`; Words filters and sorts; Home snapshot, vocabulary index and observation; the Card-to-Entry lookup resolves live Entries only; Add queries; Entry draft change detection, ordered save, suggestion provenance and the duplicate-text confirmation; bulk status, bulk tag (only adds) and bulk delete; new words per day clamped to 0–50. |
| Export / restore | `StoreTests` | JSON round trip, and restoring the same file twice changes nothing; export file names use the local day; the CSV attribution row appears only with Wiktionary-derived text; Remove all data recreates the defaults and clears the cloud state. |
| Change notifications | `ChangesTests` | A capture emits a vocabulary change; the outbox grows only while syncing. |
| GRDB gates | `ToriStoreTests/GRDBGateTests`, `ToriDictionaryTests/GRDBGateTests` | Migration, pool write and observation; FTS5 match on an immutable read-only dictionary file. |
| Sync engine | `ToriSyncUnitTests` | Backoff from 5 s to 15 min; first sync uploads and a second device adopts the generation; concurrent first syncs share one generation; zone deleted in iOS Settings stops sync and keeps words; Delete iCloud data stops the other device, and Back up again re-creates the zone; a zone re-created by another device means cloud deleted; iCloud off keeps queueing and pushes when back; an account switch merges silently; a stale change tag merges the server copy and re-sends; an existing record without local system fields is a conflict, then saved; retried and `unknownItem` records are sent again; a failed record is excluded and the rest saved; `limitExceeded` halves the batch; `changeTokenExpired` re-fetches everything; pages follow the page limit; a saved Entry tombstone deletes the group's children from the cloud; live children of a deleted Entry are purged on sight; offline waits for network with backoff; rate limits keep the last state and retry after the cloud's delay; quota and authentication errors map to their states; device time far from the cloud warns without blocking; Remove all data or Delete iCloud data during a cycle leave no stale token, system fields or status. |
| Practice list, progress, queue | `ProgressAndQueueTests` | Including `answeredTodayListsTodaysCardsOfActiveEntries`, mirrored on Android. |
| Review session, reminders, widget text | `ReviewSessionTests`, `ReminderPlanTests`, `WidgetDisplayTests` | Session order and the Forgot re-show position; reminder times before 04:00 fire on the next calendar date and past times are dropped; widget display strings. |
| App Group contracts | `ToriSharedTests` | The inbox file, vocabulary index, sticky file and widget snapshot match their documented examples; atomic writes leave no temporary file; inbox listing order; deep links. |
| Share capture | `ShareCaptureTests` | Safari selection and URL-only text, sentence and highlight, sticky offers, related offers. |
| Main-thread handoff | `MainThreadHandoffTests` | Work handed to the main thread runs once, also when started off the main thread. |
| Enrichment and Add | `ToriEnrichmentTests`, `DictionaryIntegrationTests`, `AddDraftTests`, `TranslationBridgeTests` | Suggestion order and dedupe; dictionary fill with provenance; machine translation only without a dictionary hit, its retry and `unavailable` rules; a user field is never overwritten; voice choice; autocomplete and Add screen rules. `TranslationBridgeTests` need Apple's Translation framework and run only on macOS. |
| UI models | `SwayModelTests`, `SentenceMarkupTests` | Header sway: settling, peak after one tap, kicks adding up, limits. Sentence highlight split by UTF-16 range, emoji and accents. |
| Environment | `EnvironmentTests` | The fixture locator finds `fixtures/`; SHA-256 matches a known vector. |

Not yet implemented: tests for the `CloudKitDatabase` adapter against real CloudKit (error mapping, system fields), for the app target (`SyncCoordinator` triggers, launch, background refresh), and UI tests.
