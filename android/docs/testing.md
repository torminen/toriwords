# ToriWords for Android: testing and parity fixtures

Android and iOS are separate native implementations that share no code. They must behave identically wherever the shared rules apply: text keys, IDs, clocks, merge, capture text rules, FSRS-6, the day model, the daily queue, the widget snapshot and multi-device sync. The shared definition of that behaviour is the set of JSON fixtures in `spec/fixtures/`. This file says how the Android suites run them, how the iCloud-flavoured sync scenarios map onto the Google Drive fake, and which behaviour is covered by Android-only tests.

## 1. Rules

- **Fixtures are normative.** If this specification and a fixture disagree, the fixture wins and the text is fixed. The case format, comparison rules and the exact text-function character lists are in `spec/fixtures/README.md`. Each fixture kind has a JSON Schema in `spec/fixtures/schema/<kind>.schema.json`.
- **No per-platform skips.** `spec/fixtures/known-deviations.json` must be `[]` before any release; CI blocks a release build otherwise.
- **Shared behaviour starts with a fixture.** A bug found on Android in shared behaviour gets a fixture first. Then both platforms are fixed. Case IDs are stable and never renumbered or reused.
- **Fixtures are read in place**, never copied into the Android tree.
- **Time is always explicit.** Tests never read the system clock or time zone. Every `now`, `reviewedAt` and `utcOffsetMin` comes from the case through `core`'s `Clock` interface.
- **Comparison:** integers (days, intervals, counts, stage, offsets) exactly; `stability` and `difficulty` within a relative tolerance of `1e-9`.
- **Validation first.** CI validates every fixture against its schema before the platform suites run (`cd tools/fixtures && uv run python validate.py && uv run pytest`, the shared `tools.yml` job). The same job checks that the generated `scheduler/` files are not stale and that fixtures use only code points assigned in Unicode 13.0, the ICU floor of Android 12.

| Folder | Files | Android code under test |
|---|---|---|

| `spec/fixtures/ids/` | UUIDv5 names and namespace, UUIDv7 layout, byte order | `core` ID generation and the unsigned `RecordId` comparator. |

| `spec/fixtures/merge/` | field comparator, envelope merge (incl. partial envelopes) | `core` merge. |
| `spec/fixtures/capture/` | clean, extract, typed highlight | `core` capture text rules ([capture-and-enrichment.md](capture-and-enrichment.md)). |
| `spec/fixtures/scheduler/` | FSRS step and replay, day boundary, queue files (`queue-*.json`), snapshot | `core` FSRS-6, replay fold, day model, daily queue, snapshot day counts ([scheduler.md](scheduler.md)). These files are generated by `tools/fixtures/`. |
| `spec/fixtures/sync/` | multi-device scenarios, one per file | The real `store` + `SyncEngine` for several simulated devices against the Drive fake ([Sync scenarios](#4-sync-scenarios-on-the-drive-fake)). |

## 3. Suites

| Suite | Where it runs | When | Fixture folders | Notes |
|---|---|---|---|---|
| **Host unit** | `core` JVM module, JUnit 5 `@ParameterizedTest` + `@MethodSource`, one argument per case `id` (the test name prints the ID) | Every CI run that is not path-skipped | `normalization/`, `ids/`, `hlc/`, `merge/`, `capture/`, `scheduler/` | Plus the Android-only `core` unit tests below. |
| **Host scenario** | `store` and `sync` modules with Robolectric; Room on `BundledSQLiteDriver`, in memory | Every CI run that is not path-skipped | `sync/`, plus `normalization/text-order.json` through the real queries | Several `UserStore` + `SyncEngine` instances, one per simulated device, sharing one Drive fake. |
| **Instrumented** | AndroidX Test on emulators **API 31** and **API 37** | Before each release, and on changes under `spec/fixtures/**` | **all** folders | Same code on ART, to catch differences from the host JVM (Unicode tables, `StrictMath`, SQLite build, `java.net.IDN`). |
| **Migration** | `store`, Room `MigrationTestHelper` (instrumented) | Every change to `store/schemas/`, and before release | — | A fixture database of every historical Android schema version migrates to the current one with identical logical content ([data-model.md](data-model.md#7-migrations)). |
| **Macrobenchmark** | `baselineprofile` module on a device or emulator | Before release | — | Generates the Baseline Profile and checks the performance targets ([architecture.md](architecture.md#14-performance-targets)). |

**Fixture location.** `core`, `store` and `sync` add `spec/fixtures` (relative to the repository root, e.g. `../../spec/fixtures` from a module) as a test resource directory. The instrumented test APKs add it as `androidTest` assets. A system property / instrumentation argument `toriFixtures` may point at another checkout, like `TORI_FIXTURES` on iOS.

**Unicode on ART.** The JVM and ART ship different Unicode tables. The quote, dash, space and ignorable maps are explicit code-point lists in `core`, so they cannot differ. General-category checks (punctuation, letters) use the platform tables; the instrumented run on API 31 proves those tables agree on every fixture character.

## 4. Sync scenarios on the Drive fake

The scenarios in `spec/fixtures/sync/` are written against an iCloud-like cloud: zones, change tags, accounts, `iCloudOff`. The Android scenario runner executes the same files against an in-memory **Drive fake** that models the Drive appDataFolder as Android uses it ([sync.md](sync.md)):
- files with fileIds and non-unique names, plus `appProperties`;
- `createdTime`/`modifiedTime` from the scenario's cloud clock (`start` + `t`);
- `changes.list` paging with `removed` entries and page-token invalidation;
- in-place `files.update` rewrites with no precondition;
- the `generation.json` marker, including duplicate markers created by a race;
- scripted 401 / 403 (`rateLimitExceeded`, `storageQuotaExceeded`) / 429 / network errors.

Like the iCloud fake, it never merges: every device merges and purges itself.

### 4.1 Op mapping

| Fixture op / field | Drive fake meaning |
|---|---|
| `enableSync` (`account`) | The device authorizes Google account `account` (`driveAccount` set), then runs one sync cycle. |
| `sync` | One sync cycle. |
| `sync` / `enableSync` with `limit` | Number of envelopes per `changes.list` page and per apply chunk (one transaction each). |
| `sync` with `racedBy: <device>` | That device's whole cycle runs between this device's fetch and its first upload. On Drive, uploads are new immutable files and never conflict, so the race resolves by merging on the next pull rather than by a rejected save. |
| `cloudOff` | Authorization becomes unavailable on the device (no token). No cycle runs. |
| `cloudSwitch` (`to`) | A different Google account is authorized (the `driveAccount` hash changes): local words merge silently into that account's Drive. No cycle runs. |
| `deleteCloudData` | "Delete Drive data…" in the app: every file in the appDataFolder is deleted and this device sets `driveDeleted`. |
| `deleteCloudData` with `inSettings: true` | "Delete hidden app data" in Drive's Manage apps: all files disappear without any app action. |
| `backUpAgain` | "Back up this device again". |
| `upgradeSchema` (`account`, `records`) | A batch file from an unknown device (layout 1) is written straight into that account's appDataFolder, holding the given records of a newer app version (higher `schema`, unknown fields or types). |
| `network` (`online`) | The fake answers every call from that device with a network error while offline. |
| `setClock` (`offsetSec`) | The device clock is offset from the cloud clock. |
| `capture`, `editField`, `enrich`, `review`, `exclude`, `resume`, `delete`, `tag`, `untag`, `mergeByEdit`, `setSettings` | The same app-level `store` use cases the UI calls. |

### 4.2 Expected-state mapping

| Fixture `expected` | Drive reading |
|---|---|
| `devices.<name>.sync.state` `synced` | Drive sync on, outbox empty, no error status. |
| `devices.<name>.sync.state` `cloudDeleted` | `driveDeleted = 1`, status "Drive data was deleted". |
| `iCloudOff` (state name) | Drive sync on but no authorized account. |
| `devices.<name>.sync.user` | The authorized account (`driveAccount`) the fake knows as that name. |
| `devices.<name>.sync.outbox` | `pending_changes` rows. |
| `devices.<name>.words`, `settings`, `tombstones` | Read from `user.sqlite` exactly as on iOS. |
| `cloud.<account>` Entry counts and per-type record counts | Computed over the fake's current files for that account: all envelopes are merged per record ID (the same envelope merge as the devices use), then counted. |
| `cloud.<account>.purged` | No file of that account holds a non-tombstone envelope of the purged Entry or any envelope of its children. |
| `converged` | These devices hold identical synced and derived rows; device-local columns and hidden children of deleted words are left out (as on iOS). |

Per-scenario notes:
- The clock-ahead scenario uses Drive `modifiedTime` as cloud time.
- The cloud-deletion scenario (one device deletes, the other stops and can back up again) must reach `driveDeleted` on the other device.
- A duplicate `generation.json` created by a race must **not** trigger `driveDeleted` (an Android-only test below).

## 5. Android-only tests

Not part of the shared fixtures; plain JUnit (host) unless noted.

| Area | What is tested |
|---|---|
| Share text split | URL extraction from shared text and title, trailing punctuation trim, wrapping-quote removal, link-only share, Chrome `#:~:text=` fragments giving the same Source ([capture-and-enrichment.md](capture-and-enrichment.md)). |
| Source app | Caller package → label resolution; chooser, own package and unknown callers give NULL (Robolectric). |
| Practice list | `core`'s "answered today" set: Cards of active Entries with a rated log on today's review day; paused or known Entries and logs before today excluded; compared as a set. The same cases as the iOS test `ProgressAndQueueTests.answeredTodayListsTodaysCardsOfActiveEntries`. |
| Edit-suggestion provenance | A picked suggestion saves its dictionary provenance; editing translation, definition or part of speech turns it into a user Sense; removing a meaning offers its suggestion again ([data-model.md](data-model.md#33-sense)). |
| Header sway model | Port of iOS `SwayModelTests`: peak angles after one tap, kicks adding up, limits, return to rest, leaf fall every 5th tap ([architecture.md](architecture.md#11-header-sway-model)). |
| Haptics helper | Event selection by API level (34+ gesture-threshold constants, 31–33 `CONFIRM`/`CLOCK_TICK`), composition delays computed from primitive durations, fallback to one predefined click when primitives are unsupported ([architecture.md](architecture.md#9-haptics)). |
| Swipe arming | Crossing ±10° arms, falling back disarms, release grades the armed rating only. |
| Alarm arithmetic | Next 04:00 boundary and next reminder time across DST changes and time-zone changes; reminder times between 00:00 and 04:00 belong to the previous review day ([scheduler.md](scheduler.md)). |
| Start-up | Fresh install, restore detection by `device-marker` (new Device ID, Drive bookkeeping reset, every record pending) and "Clear storage" (Robolectric) ([architecture.md](architecture.md#7-start-up-first-run-restore-and-reinstall)). |
| Drive transport | Duplicate `generation.json` race (silent adoption, no `driveDeleted`); stray uploads from a deleted generation; compaction and `covers`; purge rewrite keeps unknown fields and types; concurrent rewrites converge; files with a higher `layout` are never applied, rewritten or deleted; error mapping (401, 403, 429, 410, 413) ([sync.md](sync.md)). |
| Export / restore | CSV columns and quoting; attribution row present only with Wiktionary-derived text; JSON round trip; restoring the same file twice changes nothing; an iOS-made backup file restores ([data-model.md](data-model.md#9-export-and-restore)). |
| Backup rules | `data_extraction_rules.xml` excludes `no_backup/`, sticky fields and cache, and excludes `device-marker` from device transfer (lint-style XML check). |
